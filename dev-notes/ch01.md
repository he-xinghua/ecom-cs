## 阶段 1：brainstorm 定稿

**① 关键原话**
> 「全程走 Superpowers 流程，技能自动触发；产出不是可单测代码的任务（纯 Prompt、数据类），把 TDD 那步换成拿标注样例或评估集跑一遍验证，其余步骤照走；聊天页面是例外，用 Vibe Coding 方式直接做……不套 brainstorm、TDD、code review 那套流程」
> 「涉及具体库、框架、API 的用法……一律先用 Context7 MCP 查最新官方文档和接口定义再动手，别凭记忆写，版本对不上的 API 是返工重灾区」
> 「上面点名的技术选型是定死的，实现中发现矛盾或走不通，停下来问我，不要自行换方案」

**② 关键产出**
- Spec：`docs/superpowers/specs/2026-09-15-ecom-cs-ch01-design.md`（已自审：修掉「confidence 语义」与「expected_resolution 判定口径」两处歧义）
- 分类：**architectural 路径**（新项目，非 bounded）
- 通过 Context7 + WebSearch 核实的接口事实（均为实测/官方文档，非记忆）：
  - `trim_messages` 完整签名；**`include_system` 默认 `False`**；`token_counter` 接受字面量 `"approximate"`
  - LangChain 已是 **1.x**，主线为 `init_chat_model` / `create_agent` / middleware；0.x 的 `ConversationBufferMemory` 等写法已不在主线
  - `ChatOpenAI` + 自定义 `base_url` 的官方警告：只保证官方 OpenAI 规范，代理特有字段可能不被保留

**③ 拒绝/纠偏**
用户四次拍板，其中一次是对**我提出的技术矛盾**的纠偏：

| 问题 | 用户选择 | 被否决的选项 |
|---|---|---|
| 会话历史归谁存 | **服务端内存表** | 无状态客户端传全量；SQLite 落盘 |
| 结构化抽取落地形态 | **独立端点 `/extract`** | 对话流内旁路自动抽取；两者都做 |
| 聊天页面是否进 ch01 | **不进，延后到后续章节** | ch01 末尾顺带做极简页；页面优先做 |
| **结构化输出跨 provider 矛盾** | **方案 A：method 按 provider 配置化** | 统一 `function_calling`；原生 SDK 分家 |

**最重要的一次纠偏**：我原设计把「用 `with_structured_output`」当成直白需求，核实后发现它与「四家模型统一走 OpenAI 协议」**存在真实矛盾**——没有任何单一 method 在四家上都有 schema 保证，且失败是**静默**的（不报错，只给错 JSON）。按用户「工作要求 4」，停下来提问而非自行换方案。用户拍板 A：不换选型，加一层薄的能力表 + Pydantic 校验 + 重试兜底。

**④ 翻车与返工**
- **设计初稿被自己推翻**：初稿写「system 必须独立保留在裁剪之外」，但未意识到 `trim_messages` 的 `include_system` **默认是关闭的**。若不显式传 `True`，客服 System Prompt 会被整条裁掉，且不报任何错。这类「默认值反直觉 + 静默失败」已两次出现（另一次是 provider 的 method），列为本章重点防范模式。
- **`token_counter` 的选型修正**：原本想传模型对象做 token 计数，实测文档后确认那会走 tiktoken——而 tiktoken 对 DeepSeek / Claude / Ollama 的分词不适用，token 预算控制会失真。改用手面量 `"approximate"`，四家口径统一。
- 环境限制记录：本仓库**未安装 `elements-of-style` 技能**，spec 为手写，未调用该技能。

**⑤ 本阶段遗留的实测项（不凭记忆断言，进实现前必须验证）**
1. `ChatOpenAI.with_structured_output` 在 LangChain **1.4** 的默认 `method` 究竟是什么
2. Anthropic OpenAI 兼容层对 `function_calling` 的实际可用性（文档称 `strict` 被忽略但基础调用可用）
3. Ollama OpenAI 兼容端点对 `response_format` 的实际处理（官方声明与社区 issue 报告不一致）
